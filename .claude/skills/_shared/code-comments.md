# 代码注释的分级规范（learn / review 共用）

> 这不是一个 skill，是被学习技能引用的参考文件。

## 为什么要分级

用户反馈：demo 动辄两三百行、每行都有注释，读的时候**分不出主次**——不知道哪些是必须掌握的知识点本体，哪些只是让 demo 能跑起来的辅助代码。全部平铺直叙地注释，等于没有重点。

所以从现在起，**每一段注释都要带上重要程度标记**，让用户能决定"这段细读、这段扫一眼、这段直接跳过"。

## 三个等级

用**方括号中文标签**，写在注释的最前面。选方括号是因为它可以被 `grep` 精确提取。

| 标记 | 含义 | 典型内容 |
|---|---|---|
| `[核心]` | **必须掌握**。本次知识点的本体，面试会问，写业务代码一定会用到 | 关键 API 的调用方式与契约、决定行为的参数、数据在各阶段的形态、会静默失败的地方 |
| `[了解]` | **扫一眼就行**。知道有这回事，用到时回来查 | 参数的替代写法、"换成另一种写法会怎样"、性能取舍、边界情况、版本差异 |
| `[脚手架]` | **可以直接跳过**。与知识点无关，只是让 demo 跑起来、输出好看 | 打印格式化、终端对齐、造测试数据、`banner()` / `preview()` 这类工具函数、路径拼接 |

### 用法示例

```python
# [核心] chunk_size 的单位由 length_function 决定，默认 len 也就是字符数。
#        对接嵌入模型时必须换成 token 计长，否则中文会超出模型上限被静默截断。
chunk_size=200,

# [了解] chunk_overlap 经验值是 chunk_size 的 10%~20%。
#        设成 0，边界处的句子会断开；设得过大，重复内容会膨胀存储和检索噪声。
chunk_overlap=40,

# [脚手架] 把换行换成可见的 \n 再截断，纯粹为了终端输出好读，与知识点无关。
one_line = text.replace("\n", "\\n")
```

### 函数级标记

每个函数的 docstring 第一行前面也要带标记，让用户扫一遍函数列表就知道该读哪几个：

```python
def split_recursively(chunks: list[Document]) -> list[Document]:
    """[核心] 递归切分：把过长的块二次切到 chunk_size 以内。"""

def banner(title: str) -> None:
    """[脚手架] 打印分节标题，与 RAG 本身无关。"""
```

## 文件头的阅读地图

每个生成的 demo 文件，模块 docstring 末尾加一段**阅读地图**，按函数名（不用行号，行号会过时）说明读的顺序和取舍：

```python
"""
...（文件说明）...

阅读地图
    必读：build_embeddings()  —— 查询端与文档端为什么要配两套参数
          raw_faiss_demo()    —— 索引只返回下标这件事
    扫读：show_normalization() —— 归一化的数学原理，结论记住就行
    跳过：banner() / oneline() —— 终端输出用的工具函数
"""
```

## 硬性约束

- **`[核心]` 的注释量不能超过全文注释的三分之一。** 什么都标核心等于什么都没标。标不下的就降级到 `[了解]`。
- **三个等级都要出现。** 一个 demo 里如果一条 `[脚手架]` 都没有，说明分级没有真正做——打印、格式化这些代码一定存在。
- **标记只加在注释块的开头**，一个连续的注释块用一个标记，不要每行都标。
- 分级是**对用户的价值判断**，不是对代码复杂度的判断。一行很难懂但用不上的代码是 `[了解]`；一行很简单但决定成败的参数是 `[核心]`。
- 讲解正文里提到某段代码时，可以直接说"这段标了 `[核心]`"，让标记和讲解对得上。

## 用户可以怎么用这套标记

在输出的最后提示一次（只在第一次生成带标记的文件时提示，之后不用重复）：

```powershell
# 只看必须掌握的部分
Select-String -Path rag_05_xxx.py -Pattern "\[核心\]" -Context 0,3
```
