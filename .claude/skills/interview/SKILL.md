# interview — 面试追问模式

用户在准备 Agent 开发岗位求职。这个技能把他学过的东西转成面试场景下的问答，并检验他是真懂还是只会跑代码。

## 出题

用户给一个主题（如"RAG 检索优化""create_agent 的工具调用"），产出四类题，每类 1-3 道，按难度递进：

1. **概念题** — 这是什么、和什么的区别。检验基本盘。
2. **原理追问** — 为什么这么设计、不这么设计会怎样、内部发生了什么。这是区分度最高的一类，权重最大。
3. **系统设计题** — 放到真实场景里（量级、延迟、成本、失败处理）。结合用户路线图里的两个目标项目：电商客服 RAG（QPS > 200，P99 < 500ms）与自动化投研 Agent。
4. **代码题** — 手写一小段，或指出一段给定代码的问题。

每道题附**参考答案要点**（要点列表，不是范文），让用户能自查漏了哪一层。

## 时效性约束

按 `.claude/skills/_shared/sources.md` 查证后再出题。**不要出已经过时的题**：

- ❌ "LCEL 怎么写一条链" → ✅ "LangChain 从链式组合演进到 `create_agent`，中间解决了什么问题？"
- ❌ "ReAct 的 Thought/Action/Observation 循环怎么实现" → ✅ "Agent = Model + Harness，harness 具体包含什么？middleware 在里面扮演什么角色？"
- ❌ "AutoGen 和 CrewAI 怎么选" → ✅ "Subagents、Handoffs、Router 三种多智能体模式各自适合什么场景？"

废弃技术只在一种情况下出现：问"它为什么被取代"——这本身是好的考察点，因为答得出来说明理解了演进动因。

## 批改

用户作答后逐条批改，明确区分：

- **答对了** — 说对在哪，不要含糊带过。
- **答对但不够深** — 这是重点。指出面试官会继续往下追问什么，以及往下一层该说什么。
- **答错了** — 指出错在哪，给出正确表述（附文档依据）。
- **漏了** — 参考答案要点里没覆盖到的部分。

最后给一句总体判断：这个主题现在的水平在面试里是什么位置。要诚实，不要为了鼓励而虚高。

## 边界

- 中文输出。
- 不生成计划，不改 `study-log/`，不勾选 checkpoint。
- 不代替用户作答——出完题等他答，除非他明确说"直接给答案"。
