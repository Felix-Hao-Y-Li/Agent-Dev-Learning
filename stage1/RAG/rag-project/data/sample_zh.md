# RAG 系统设计手册

检索增强生成（Retrieval-Augmented Generation，RAG）把「检索」和「生成」两件事拼在一起：先从外部知识库里找出与问题相关的片段，再把这些片段塞进提示词交给大模型作答。它解决的核心问题是大模型的知识截止日期和幻觉。

## 一、索引阶段

索引阶段是离线完成的，它决定了在线检索的天花板。如果这一步把文档切坏了，后面用再强的重排模型也救不回来。

### 1.1 文档加载

文档加载负责把 PDF、Word、HTML、Markdown 等异构格式统一成纯文本加元数据的结构。PDF 是最麻烦的一种：它本质上是一份「绘图指令」，并不保存段落、表格、阅读顺序这些语义结构，所以从 PDF 里抽文字天然是有损的。双栏排版的论文如果按坐标顺序硬抽，会把左右两栏的句子交错在一起，读起来完全是乱码。

### 1.2 文本切分

切分要在两个矛盾的目标之间取平衡。块太大，一次检索会带回大量无关内容，稀释了真正有用的那几句话，还会挤占上下文窗口；块太小，一句话的主语和谓语可能被切到两个块里，单独看哪一块都不知道在说什么。工程上常用的起点是每块 500 到 1000 个 token，块之间保留 10% 到 20% 的重叠。

### 1.3 向量化

向量化把每个文本块映射成一个固定维度的浮点数数组，语义相近的文本在这个空间里距离也近。需要注意嵌入模型自身有最大输入长度，超长的块会被静默截断，这是切分参数没设好时最隐蔽的一种数据丢失。

## 二、检索阶段

### 2.1 向量检索

向量检索用余弦相似度或内积在向量库里找最近邻。它擅长处理同义改写，但对专有名词、型号、编号这类字面匹配反而不如传统的关键词检索。

### 2.2 混合检索

混合检索同时跑 BM25 关键词检索和向量检索，再用 RRF（Reciprocal Rank Fusion）之类的方法把两个排序融合起来，兼顾语义泛化和字面精确。

## 三、常见误区

一个高频误区是把切分当成纯字符串操作，忽略了元数据。块的来源文件、页码、所属章节标题都应该跟着块一起存进向量库：召回之后要靠它们给用户展示引用出处，也要靠它们做按部门、按时间的过滤检索。
